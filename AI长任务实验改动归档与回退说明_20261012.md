## 2. 起因与第一轮修改

第一次日志分析指出：工具标签、原生参数 JSON、额外 params 包装和文本匹配错误反复出现。42 次工具成功、36 次失败并不代表任务完成；2.4 笔记在例 2.38 附近中断，2.5 和旧笔记补充仍不完整。历史仅保留少量原始请求，单个长用户轮次难以压缩，缺少完整目标和验收状态。

分析时区分了 HTTP/服务异常与模型生成的协议、参数、验收错误，不能把全部失败归因于网络。

### 2.1 原生工具协议

- 保存 assistant.tool_calls 与匹配的 tool.tool_call_id；分离 UI 标签正文和实际 API 正文。
- 兼容旧标签批次时只转换工作上下文，不改写原始聊天记录。
- 原生模式拒绝执行正文工具标签；参数 JSON、额外包装、未知参数和未启用工具在写入前校验。
- 保留 DeepSeek 所需思考字段，不把 UI 标签重新当成模型工具指令。

### 2.2 五个新增工具与任务状态

| 接口 | 功能 | 关键参数 |
|---|---|---|
| get_task_progress | 获取全部目标、状态、关联笔记、资料目录和断点 | 无 |
| task_plan | 补充步骤、验收标准和来源，保留原始目标 | steps；id/title/criteria/requiredSections/requiresWrite/sourceRefs |
| task_step | 更新 pending/running/done/blocked，完成需证据 | stepId/status/evidence/error |
| read_ai_attachment | 按消息、附件索引、页码或文本偏移读取原始资料 | messageId/attachmentIndex/page/offset/limit/mode |
| finish_note | 版本、结构、必需章节和来源检查，通过后解除草稿 | id/revision/stepId/requiredSections/sourceRefs |

新增 task 工具组。原有写工具扩展 stepId/chunkId，add_note 增加 draft。

检查点 conv._aiTask 保存目标、步骤、当前步骤、笔记 ID、写入凭据、草稿、来源窗口、失败记录和执行事件。增加任务进度与“从断点继续”，区分继续和重新生成。

### 2.3 上下文与预算

- 固定当前用户要求和检查点，按完整 assistant/tool 批次保留最近工作历史。
- 工具 schema、工具参数、思考历史和图片预留纳入估算，服务端 usage 用于校准。
- 增加可选的模型输入加输出总上下文容量，并限制输出占用。
- 完整消息树仍存储；压缩仅作用于工作上下文。
- 原始附件沿用 originalFileId，避免在任务状态中重复持久化图片 base64。

### 2.4 写入与验收

- 稳定 chunkId 按步骤、动作和目标去重，跨刷新和版本变化后仍防重复追加；长期片段凭据独立于滚动日志。
- 任务状态和笔记等混合模块写入发生失败时整体回滚。
- 分段笔记保存为草稿，验收前暂不参与复习，通过后恢复原复习设置。
- 检查折叠块、公式分隔符、明显转义错误、占位内容和必需章节。
- 自然语言 criteria 与具体标题 requiredSections 分开。
- 需要写入的步骤必须有成功凭据，不能只靠一句 evidence 宣称完成。

### 2.5 请求与诊断

- 请求前超时和瞬态网络/HTTP 错误按策略重试，退避期间可取消。
- 流式提前结束且没有完成标记时，不执行半截工具参数。
- 按容量保留实际请求协议、工具定义、usage、结束原因和错误；内联图片脱敏，不记录 Authorization 头。
- 独立保留有界执行事件。正常压缩存储与异常降级路径均保留关键任务状态。

## 3. 第二轮：222.log 暴露的问题和修复

### 3.1 实际执行结果

日志这轮的成功工具操作：get_task_progress 1 次、get_note_detail 8 次、read_ai_attachment 7 次、task_plan 2 次、get_note_outline 1 次，共 19 次。

同一轮另有 3 次 read_ai_attachment 失败；没有 add_note/update_note/patch_note/append_note 写入。

最后三个 PDF 读取省略了旧附件消息的 messageId。接口默认查找最新“继续任务”消息，但该消息没有附件，因而报附件索引无效。三个同轮失败立即耗尽预算，模型没有下一轮纠错机会。

还发现图片批次只留下最后一页，工具“读取成功”不等于所有页面实际送入模型请求。

### 3.2 修复内容

1. 当前消息无附件时默认沿用已选来源或最近带附件的历史消息；显式错误 ID 不静默换文件，返回 sourceCatalog。
2. 按步骤聚合同轮失败，保留下一轮纠错机会；跨轮预算保留，手动继续开启新尝试。
3. 同批明确选定的最多三页全部送入请求并标注顺序；同批文本读取不覆盖待发送图片。
4. 恢复来源窗口，避免历史整份 PDF 重复发送；普通单图追问和已上传 file_id 保留连续性。
5. 图片需实际进入成功模型请求才记为 delivered；待发送页面不能通过验收。
6. 显式 text 模式覆盖原先 PDF image 模式；扫描页无文本时明确要求图片读取。
7. 自然语言“继续”沿用未完成目标与凭据；无检查点的旧对话找回原始编号目标，并修复第一次版本留下的通用继续检查点。
8. 固定用户明确选择的 skill 快照；附件和插入参考笔记仍作为资料。
9. 附件级计划 sourceRefs 可匹配实际读取窗口；成功完成后清除过时的 lastError。

## 5. 用户发现的代价与回退原因

read_ai_attachment 的读取粒度过细：每次一个 PDF 页面、同批最多三图、文本默认 6000 字且最多 8000 字。大量资料需要频繁工具调用和模型往返，导致一个 turn 过长。

来源记录不等于可复用正文索引；文本可能重复读取原文件、PDF 可能重复解析。窗口切换和工具结果离开上下文后，模型还可能重读。缓存页面也不自动解决模型往返和重复输入 Token。

成功读取不能代表产出笔记，所以稳定协议与严格验收并未保证整体任务效率。用户选择撤回本轮实验，保留经验与代码快照。

以下只是方案，不是已交付代码：

- 应用负责资料准备，AI 通常直接处理资料包、产出笔记，异常时再补读。
- 分阶段执行上下文与阶段进度，避免主对话单个 turn 堆积冗长过程。
- 来源范围、核对状态、笔记片段关联及验收记录复用。
- 以模型往返次数、输入 Token、重复读取率、首个有效写入时间和内容覆盖率衡量效果。

没有实现 read_ai_sources 或自动资料包执行器。

+长任务现在按原始用户目标保存执行检查点。附件和日志中的文字属于资料，不作为新的执行指令。
+
+- 支持原生工具的接口使用 assistant.tool_calls 与匹配的 tool_call_id；兼容旧标签历史时只转换工作上下文，不修改聊天记录。原生模式不执行正文工具标签。
+- task_plan 保留原始目标，可增加步骤、验收标准、必需章节和来源。task_step 的完成声明需要说明实际结果；要求写入的步骤需要成功凭据。工具成功次数单独展示，不表示任务完成。
+- 输入预算包含工具 schema、工具参数、思考历史和图片估算。长工具链压缩完整调用批次，固定当前用户要求与执行检查点。服务端 usage 用于校准估算。模型设置可填写输入和输出合计的上下文容量。
+- read_ai_attachment 按消息 ID、附件索引、PDF 页码或文本偏移读取本地原文件；图片请求默认保留一个页面，同轮明确读取的最多 3 个页面会全部进入随后请求并标注顺序；历史整份图片不会重复发送。没有显式 messageId 且当前消息没有附件时沿用最近来源或最近带附件的历史消息。缺失原文件和截断预览会明确返回不完整来源。
+- 分段笔记保存为草稿，暂不参与复习。finish_note 检查折叠块、公式、明显转义问题、占位符和指定章节，并校验来源读取记录；图片还要求实际送入成功的模型请求，不能用待发送页面通过验收。自然语言验收标准与必需章节标题分开保存。
+- 稳定 chunkId 按步骤、动作与目标去重，忽略后续版本变化。混合写入失败回滚全部相关模块和任务状态。相同步骤按失败轮次累计预算，同轮多个失败先返回完整结果，让模型有下一轮纠错机会；手动续接开启新一轮纠错预算。
+- 刷新后可从已有工具结果末尾续接；面板的“从断点继续”保留完成项。重新生成仍是独立的重新尝试。任务状态、调用 ID 和校准值经过实际存储压缩后保留。自然语言“继续”沿用未完成检查点；没有检查点的旧对话会找回原始编号目标。
+- 日志保留整个任务的有界事件记录，以及按容量保留的近期实际请求、协议字段、usage 和结束原因。内联图片数据脱敏，不记录 Authorization 头。
+
+## 验证边界
+
+结构检查和来源读取凭据不能证明逐字转录准确，也不能自动证明教材所有内容都已覆盖。AI 仍需对照原始页面进行内容核对。Token 计算是保守估算，不是服务商 tokenizer。
+
+测试使用隔离数据和模拟服务端响应，覆盖原生工具链、长上下文、事务、来源续读、草稿验收、保存与重载、去重、错误预算和 Electron 续接按钮。未使用用户真实 API Key 重新运行原日志的付费长任务。
