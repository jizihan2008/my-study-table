## 工具调用循环（Tool Call Loop）
- 问题：AI 调用工具（如 get_today_status）获取数据后，工具结果被展示给用户但程序没有自动再次调用 AI 继续推理，导致 AI 无法基于查询结果做后续推荐
- 方案：实现工具调用循环，AI 回复含 <tool_call> → 执行工具 → 工具结果作为 system 消息注入对话 → 自动再次调用 AI → 重复直到 AI 不再返回工具调用
- 关键改动：
  1. 提取 `callAiApi()` 和 `buildApiMessages()` 两个公共函数（js/ai.js）
  2. 新增 `runToolCallLoop()` 函数（js/ai.js），最多循环 5 次，每次自动调用 AI 处理工具结果
  3. 工具执行过程和结果完全隐藏，不展示给用户；只有最终的不含 tool_call 的 AI 回复才显示
  4. `sendAiMessage()` 和 `executeAutomation()` 都改为使用 `runToolCallLoop()`
- 涉及文件：js/ai.js（新增 3 个函数，重写 sendAiMessage）、js/settings.js（重写 executeAutomation）

## Kimi 图片/视频视觉分析修复
- **问题**：上传风景照等图片时 `uploadToKimi()` 使用 `purpose: 'file-extract'`（仅OCR文本提取），无文字的图片返回空内容导致"分析失败"
- **根因**：Moonshot API 的 file-extract 只做文字提取，不做视觉理解
- **修复方案**（根据 Moonshot 官方文档）：
  - 新增 `uploadKimiForVision(file)` 函数：上传文件获取 file-id（不指定 purpose）
  - 新增 `isVisionFile(file)` 函数：检测图片/视频类型（MIME type + 扩展名双判断）
  - 修改 sendAiMessage 附件处理逻辑：
    - 图片/视频 → 调用 uploadKimiForVision → 获得 file-id → 存入 userMsg.visionFiles[]
    - 文档(PDF/Word等) → 保持原有 file-extract OCR 方式
  - 修改 buildApiMessages：当消息有 visionFiles 时构建多模态 content 数组
    ```json
    [{"type":"text","text":"用户输入"},{"type":"image_url","image_url":{"url":"ms://<file-id>"}}]
    ```
  - 视频同理使用 video_url 类型
- 涉及文件仅 js/ai.js（4处改动）
