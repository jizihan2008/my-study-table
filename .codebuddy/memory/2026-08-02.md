## Bug 修复：笔记复习日期时区错位（同日）

用户报告：今天创建的 3 个笔记复习日期不统一（2 个明天 1 个后天）。**根因**：`js/notes.js` 的 `calcNextReviewDate` 用本地时区 `setDate(+1)` 生成日期，但所有消费端用 `toISOString().slice(0, 10)`（**UTC 日期**）与本地日期（`getTodayStr()`、日历本地格子）比较/展示。UTC+8 下本地 08:00 前创建的笔记其 UTC 日期早一天，+1 天后显示为"今天"而非"明天"。

**修复**（统一为本地日期语义）：
- `js/notes.js` 新增全局辅助 `toLocalDateStr(d)`（本地 YYYY-MM-DD，含无效日期保护）和 `daysBetweenDateStr(a,b)`（本地日期字符串整天差）；4 处改为本地：笔记列表 badge 的 dueDays（原 `nextDate - new Date(getTodayStr())` 混时区）、`getNotesDueForReview` 的日期比较、`getAllFutureReviewDates` 的两处输出（日历 map key）。
- `js/ai-tools.js` 3 处 `calcNextReviewDate(n).toISOString().slice(0, 10)` → `toLocalDateStr(calcNextReviewDate(n))`。
- `js/today.js` 2 处逾期天数计算（复习卡片 + 复习浮窗）改为 `daysBetweenDateStr(toLocalDateStr(n.nextReviewDate), getTodayStr())`。

实测验证（本地 8/2 创建）：旧逻辑 07:00→8/2、12:00→8/3、20:00→8/3（错位）；新逻辑全部→8/3（统一明天）。Lint 通过，无残留 `calcNextReviewDate(...).toISOString()`。

**第二根因（用户用备份文件验证后确认）**：`calcNextReviewDate` 的「从未复习」分支**硬编码 +1 天**，未读取 `getReviewIntervals()`（`REVIEW_PRESETS`：standard=[1,2,4,7,15,30,60,120]，relaxed=[2,4,8,15,30,60,120,240]）。导致宽松模式下：无复习历史的新笔记 → +1（明天），而被编辑过的笔记（`resetReviewOnEdit` 推入 history 后走间隔分支 intervals[0]=2）→ +2（后天），同一天创建的笔记复习日不一致。**已修复**：未复习分支改为 `getReviewIntervals()[0]`（standard 仍 +1，relaxed +2，custom 按自定义首间隔）。用备份 `study-table-backup-2026-08-02.json` 验证：3 篇今天创建的笔记（0x11 栈/0x12 队列/0x13 链表）修复后宽松模式复习日统一为 2026-08-04（后天）。注：备份 JSON 为扁平 localStorage 结构，笔记数组在 `data.study_notes_v2`（字符串需 JSON.parse），不含 `study_review_mode` key（存储位置待确认）。
