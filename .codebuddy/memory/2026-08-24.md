## 修复 40：AI 发送后输入框残留草稿（v20260824-r1/ai-send）
- 现象：AI 对话 Enter 发送后，输入框仍保留刚发送的文本（像草稿）。
- 根因：`sendAiMessage` 中 `didReRender` 分支（新对话首条消息触发 AI 自动标题 + `renderAiChat()` 全量重渲染）：`renderAiChat()` 内部开头 `saveAiDraft()`（把当前输入框内容存为草稿，此时刚发送的文本还在框里）、末尾 `restoreAiDraft()`（把草稿恢复回输入框）；而 `sendAiMessage` 末尾清空输入框的逻辑 `if (!didReRender && !fromQueue)` 被 `!didReRender` 跳过 → 草稿残留。
- 修复（`js/ai-send.js`）：`didReRender` 分支在 `renderAiChat()` **之前**先清空 `input.value`（加 `if(input)` 保护，兼容队列发送无 input），使 `saveAiDraft` 存空草稿。
- 版本：ai-send.js→20260824-r1、service-worker→mst-v66。需重启 Electron。未推送（用户暂缓）。

## 修复 42：DeepSeek Vision 报 unsupported image（v20260824-r3/ai-attach+ai-send）
- 现象：上传 PNG 到 deepseek-v4-flash-vision-exp 报 `.messages[1].image[1]: unsupported image, 支持 webp/png/jpeg/gif`。
- 排查：web 搜索确认该模型用标准 OpenAI 兼容格式（Base64 内联/URL/Files API），官方支持 webp/png/jpeg/gif。消息结构（type:image_url + image_url:{url:dataUrl}）本身正确。
- 根因：**部分来源的 PNG 文件 `file.type` 为空** → FileReader.readAsDataURL 生成 `data:;base64,...`（无 image/png MIME 前缀）→ DeepSeek 服务端嗅探不到格式 → 报 unsupported image。
- 修复：
  1. `ai-attach.js readFileAsDataURL`：按扩展名（IMG_EXT_MIME 映射 png/jpeg/gif/webp/bmp）强制修正 data URL 的 MIME 前缀（原本已有正确 MIME 则不动）。
  2. `ai-send.js` 视觉分支：bmp 图片明确提示「当前模型不支持 bmp，请转 png/jpeg」（DeepSeek 官方格式不含 bmp；Kimi 才支持）。
- **教训**：FileReader 的 data URL 依赖 file.type，空 MIME 会静默生成无类型 data URL；多模态模型对图片格式嗅探严格，必须按扩展名兜底修正。
- 版本：ai-attach.js/ai-send.js→20260824-r3、service-worker→mst-v71。需重启 Electron。未推送（用户暂缓）。

## 修复 44：任务线节点放不出去——SVG viewBox 未同步（v20260824-r3/taskline）
- 现象：任务线手动画布拖拽节点到某个边界后放不出去。
- 根因：拖拽时 `tlExpandGraphInner` 扩展 `.tl-graph-inner` 的 width/height 并同步 SVG 的 width/height，但**未同步 SVG 的 `viewBox`**（初始 `viewBox="0 0 初始宽 初始高"`）。viewBox 定义了 SVG 逻辑坐标系，width/height 变大而 viewBox 不变 → SVG 内容被缩放错位、连线偏移；同时 `.tl-graph-canvas` overflow hidden 裁剪内容，节点拖出初始 inner 范围后不可见 → 视觉上"放不出去"。
- 修复：`tlExpandGraphInner` 在扩展 width/height 时同步 `svg.setAttribute('viewBox', '0 0 新宽 新高')`，SVG 坐标系与 inner 保持一致。

### 修复 44b：任务线节点"弹回来"——tlClampGraphView 钳制范围错误（v20260824-r4/taskline）
- 现象：节点拖到画布某界限外会弹回来（拖不出去）。
- 根因：`tlClampGraphView` 钳制公式 `nl = min(cw+margin, max(-(iw+margin), left))`——下界 `-(iw+margin)` 把内容右缘推到视口左侧外，**内容右侧永远无法滚进视口**。拖拽时 `tlFollowNodeInView` 想左移视图跟随节点，却被 clamp 钳回 → 节点"弹回来"。viewBox 修复（r3）只是连线显示问题，真正的放置限制在这里。
- 修复：改钳制范围为 `minL = min(0, cw-iw) - margin`、`maxL = max(0, cw-iw) + margin`（top 同理）——内容比视口宽时左缘可到 margin、右缘可到 cw-margin，两侧保留 TL_PAN_MARGIN 余量但**保证节点能滚进视口**。
- 版本：taskline.js→20260824-r4、service-worker（PRECACHE）→mst-v75（VERSION 用户已改）。未推送（用户暂缓）。

### 修复 44c：任务线节点四方向自由放置（v20260824-r7/taskline）
- 用户进一步定位：**只有上/左方向拖出会回弹，右/下正常**。
- 根因：①所有坐标保存处用 `Math.max(0, ...)` 把负坐标钳制为 0（`onUp`/`onUp`touch、`tlAddQuest`、`tlUpdateQuest`、`tlQuestFormPos`）→ 拖到左/上边界外松手后 pos 被拉回 0 → 重绘回弹；②布局 `tlLayoutGraphManual` 与渲染只支持正方向扩展（viewBox 从 0 起、nodes 容器无偏移），负坐标节点会超出画布被裁剪。
- 修复（`js/taskline.js`）：
  1. 所有 pos 保存处去掉 `Math.max(0, ...)`，允许负坐标。
  2. `tlLayoutGraphManual` 计算内容范围 `minX/minY/maxX/maxY`，返回 `width=(maxX-minX)+TL_PAD`、`height=(maxY-minY)+TL_PAD` 和 `minX/minY`；自动布局返回 `minX:0,minY:0`。
  3. 渲染：nodes 容器 `style="left:-minX;top:-minY"` 整体平移（负坐标落入画布可视区），SVG `viewBox="${minX} ${minY} W H"` 保持连线坐标对应。
  4. `tlExpandGraphInner` 四方向扩展：读取 nodes 容器当前平移量，计算节点实际坐标 `offsetLeft+shift`，按 min/max 边界重算 inner 尺寸、viewBox 起点与 nodes 平移。
  5. `tlFollowNodeInView` 视口坐标加上 nodes 平移 `offsetLeft+shiftX`。
- 版本：taskline.js→20260824-r7、service-worker（PRECACHE）→mst-v75。未推送（用户暂缓）。

### 修复 44d：拖拽画布闪烁（v20260824-r8/taskline）
- 用户反馈：负坐标拖拽已可用且松手位置正确，但**拖动过程中画布闪烁**。
- 根因：`tlExpandGraphInner` 在每次 mousemove 中修改 nodes 容器平移（left/top）与 SVG viewBox → 所有节点视觉位置逐帧跳动 → 闪烁。
