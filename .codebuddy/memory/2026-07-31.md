## 设置弹窗中的「待办状态管理」编辑按钮不可见 Bug

**问题**：用户反馈"设置 → 数据 → 待办状态管理 → 编辑（铅笔）按钮点击没有用"。

**排查过程**（使用 Electron + executeJavaScript 模拟真实鼠标 click）：
1. `editBtn.click()` 和 `dispatchEvent(new MouseEvent('click'))` 都正常触发 `openStatusEditor`，popover 的 `style.display` 变成 `block`。
2. 但**真实鼠标**（`sendInputEvent` mouseDown+mouseUp）点击后，popover 的 `style.display` 仍是 `none`。
3. 进一步诊断 `elementFromPoint(cx, cy)` 返回 `null` —— 点击坐标上没有元素！
4. `getBoundingClientRect()` 显示按钮在 `y=850`，而窗口高度只有 `837` —— **按钮本身在 modal 滚动容器之外（被裁剪）**。
5. 用 `editBtn.scrollIntoView({block:'center'})` 滚动后真实点击，popover 成功变为 `block` —— 证实按钮在视口内时点击有效。
6. 检查 popover 位置：`rect: {top: 712, bottom: 894, height: 182}`，窗口高 `837` —— **popover 显示在屏幕可视区域之外**！

**根因**：`renderStatusList()` 把 `statusEditPopover` 作为普通流式 `<div>` 渲染在 `#settingsTodoStatuses` 容器内（列表末尾）。设置弹窗的 `.modal-body` 是 `overflow-y: auto` 滚动容器（max-height: 70vh）。当用户点击列表中的铅笔按钮时，`openStatusEditor` 把 popover `display` 设为 block，但 popover 出现在列表末尾 —— **可能位于 modal 滚动区域之外**，用户完全看不到，所以误以为"点击编辑按钮没用"。`.status-mgmt-item` 上的 `draggable="true"` 没有拦截简单 click（dragFired=0, clickFired=1），不是根因。

**修复**（`js/settings.js` `openStatusEditor`）：显示 popover 后，用 `setTimeout(30ms)` 找到最近的 `.modal-body` 滚动容器，若 popover 超出可视区则调整 `scrollTop` 让其完全可见。

```js
if (popover) {
  const modalBody = popover.closest('.modal-body');
  const ensureVisible = () => {
    const pr = popover.getBoundingClientRect();
    const cr = modalBody ? modalBody.getBoundingClientRect() : null;
    if (!cr) return;
    if (pr.bottom > cr.bottom) {
      modalBody.scrollTop += pr.bottom - cr.bottom + 12;
    } else if (pr.top < cr.top) {
      modalBody.scrollTop += pr.top - cr.top - 12;
    }
  };
  setTimeout(ensureVisible, 30);
}
```

**验证**：修复前 `completelyVisible: false`、`bottom: 894 > windowH: 837`；修复后 `completelyVisible: true`、`bottom: 700 < 837`，截图显示 popover 完全可见（名称输入框、颜色选择器、保存/取消按钮均在视口内）。

版本：`js/settings.js?v=20260731-r1`，`index.html` 版本号 bump。

## 调试方法沉淀

**Electron 真实鼠标点击测试技巧**：
- `editBtn.click()`（编程方式）和 `dispatchEvent(new MouseEvent('click'))` 都能触发 onclick 处理器，但**不能模拟真实鼠标事件流**。
- 必须用 `webContents.sendInputEvent({ type:'mouseDown' })` + `mouseUp` 才能模拟真实浏览器行为。
- 注意 `getBoundingClientRect()` 返回的是布局位置（未裁剪），元素可能被 modal 的 overflow 裁剪，需要检查 `elementFromPoint` 才能确认可见性。
- 对于 Electron 应用定位"点击没反应"类 bug，建议同时验证三件事：(1) 函数是否被调用；(2) 函数执行后 DOM 是否变化；(3) DOM 元素是否在用户实际可见区域内。
