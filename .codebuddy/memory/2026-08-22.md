## 学习 tab：双指捏合缩放改为围绕捏合中心

**问题**：双指缩放 PDF 的实时预览固定从页面顶部/中心缩放（`transform-origin: center top`），用户在任何位置捏合效果都一样，不跟手指。

**改动**（`js/books-study.js`，`bkStudyBindPinchZoom`）：
- `touchstart`：记录 `_pinch` 扩展为 `{d0, scale0, cx0, cy0, pageLeft0, pageTop0}`——`cx0/cy0` 为捏合中心相对 wrap 的坐标，`pageLeft0/pageTop0` 为页面元素初始 `offsetLeft/offsetTop`。
- `touchmove`：`transform-origin: 0 0`，`transform = translate(tx,ty) scale(k)`，其中 `k = s/scale0`，`px = cx0 - pageLeft0`（捏合中心对应页面内容点），`tx = 当前中心cx - pageLeft0 - px*k`——保证**手指中心下的内容不动**，缩放跟随捏合中心。
- `touchend`/`touchcancel`：仍 `_stRenderPage()` 高清重渲染（回到居中，scale 保留）。
- `index.html`：books-study.js?v=20260821-r1 → r2；`service-worker.js` mst-v17 → v18。

**局限**：松手后 `_stRenderPage` 重建 DOM 丢失平移，页面回到居中（未保持捏合位置）。如需保持可后续给 `_stRenderPage` 加 translate 记忆。

## QQ 聊天 JSONL 分块导入（v20260822-r2）— 大群导出卡死的终极方案

**背景**：用户大群（6万+条）用 qq-chat-exporter 单文件 JSON 导出卡 26%（内存吃满，官方 issue #662 同类）。实测**流式导出（= JSONL 分块）不卡死**，但输出是 `manifest.json + chunks/*.jsonl`，原导入只支持单文件 JSON。

**实测 JSONL 结构**（用户真实导出 3879 条）：
- `manifest.json` 顶层：`metadata`/`chatInfo`（同单文件：name/type/selfUin/peerUin）/`statistics`（**totalMessages** 非 total、**senders** 数组非 participants 数字、**timeRange.start(end) 是 ISO 字符串**非毫秒）/`chunked`（**format:"jsonl"、chunksDir:"chunks"、chunks[]** 含 fileName/relativePath/count/startTsMs/endTsMs）
- **`chunks` 数组在 `chunked` 内部**（不在顶层）
- 每行 `.jsonl` = 一条消息，字段与单文件 messages[] 相同（id/seq/timestamp/time ISO/sender/content.text）；`content.text` 中文正常，sender.name 是群名片

**改动**：
- `js/qq-chats.js`：`_parseChatInfo` 兼容 JSONL（totalMessages/senders 数组/ISO timeRange，新增 `_toTs` 转毫秒）；`_normalizeMessages` 兼容 ISO time（正则 `/T.*Z$|T.*[+-]\d\d:?\d\d$/` 判 ISO → `_fmtTime` 转 `YYYY-MM-DD HH:mm:ss`）；新增 `importChunkedJsonl(manifest, allMessages, opts)`（接收已解析 manifest + 全部消息数组，其余同 importJsonFile，chatId 生成一致）
- `main.js`：3 个 IPC —— `qqchat:pick-dir`（dialog openDirectory + `ensureInboxDirAllowed`）、`qqchat:read-manifest`（读 manifest.json，校验 `chunked.chunks`，resolve 各 chunk 绝对路径）、`qqchat:read-chunk`（读单 chunk 返回 items 数组，损坏行忽略）
- `preload.js`：暴露 `qqchatPickDir`/`qqchatReadManifest`/`qqchatReadChunk`
- `js/inbox.js`：toolbar 加「导入 JSONL 文件夹」按钮；`importQQChatJsonl()`（Electron 走 IPC 选目录 → 读 manifest → 逐 chunk 读 → `finishImportChunkedJsonl`）+ `importQQChatJsonlFiles()`（PWA/浏览器多选文件 fallback，找 manifest.json + 所有 .jsonl）+ `finishImportChunkedJsonl`（覆盖确认 + 写入 + 刷新）

**版本**：qq-chats.js/inbox.js→20260822-r2、main.js/preload.js（主进程无版本参数）、service-worker→mst-v23。mock IDB 测试（test-qqchats-jsonl.mjs，已删）用真实 JSONL 数据验证导入/消息数一致/检索/时间格式化全通过。

**坑**：(1) PowerShell 命令行传中文路径会被编码破坏，读取中文路径文件必须用 Node 脚本（文件内 UTF-8）；(2) JSONL 的 statistics 字段名与单文件不同，解析必须三路兼容；(3) `_buildChatId` 用 peerUin 生成，JSONL 与单文件的 chatId 一致，覆盖逻辑复用。

**后续修复（v20260823）**：用户导入 JSONL 报「读取失败：路径不在允许范围内」。根因：`main.js` 的 `isInboxPathAllowed` 用 `isPathInside(base,target)`（基于 `path.relative`），当传入路径**恰好等于白名单目录本身**时 `rel===''` → 返回 false。而 `qqchat:read-manifest` 传的 dir 就是用户刚选择的导出文件夹本身（`ensureInboxDirAllowed` 已加入白名单），被误拒。修复：`isInboxPathAllowed` 增加 `abs === base ||` 判断，放行目录自身；chunk 子文件本就走 `isPathInside` 正常通过。Node 验证：`abs===base` true / `isPathInside` false / chunk inside true。需重启 Electron 生效。

## AI 对话：滚动位置保持 + 发送队列系统（v20260822-r2）

**需求**：(1) AI 对话窗口记录当前滚动位置，AI 回复后不要每次跳到底部；(2) 发送队列：回复完成后自动发送下一条，适配输入框发送与右键选中文字。

**滚动保持**（`js/ai-render.js`）：

- `renderAiMessages()` 开头记录 `prevScrollTop` + `wasNearBottom`（距底 <120px 视为在底部），末尾：`_aiForceScrollBottom||wasNearBottom` → 滚底，否则恢复 `prevScrollTop`；渲染后重置标志。
- `renderAiChat()` 开头置 `_aiForceScrollBottom=true`（切换/重建对话视图强制滚底）；其 setTimeout 滚动同样判断标志或近底部。

**发送队列**（`js/ai-send.js` + `js/ai-render.js` + `js/ai-conv.js`）：
- `ai-send.js`：`_aiSendQueue`（项 `{convId,text,attachments}`）+ `_aiQueueDraining` 防重入；`updateAiQueueIndicator()` 更新输入区上方指示器；`drainAiSendQueue(convId)` **while 循环**处理该会话全部排队项（`isAiLoading(convId)` 或会话不匹配时暂停/break，避免死循环）。
- `sendAiMessage(externalText, externalAttachments)` 重构支持可选参数：**不传参**=手动发送，若 `isAiLoading` → 入队（清输入框+附件，提示「已加入发送队列」）；**传参**=队列自动发送（`drainAiSendQueue` 调用）。队列发送防御：`conv.id!==convId` 时 unshift 回队并停止。
- 发送完成（`setAiLoading(false)` 后）调 `drainAiSendQueue(conv.id)`；`handleAiSendOrStop` 停止时**清空队列**（停止=停止一切）。
- `ai-render.js`：输入区上方新增 `#aiQueueIndicator` 指示器；`askAiExplainSelection`（右键仔细讲解）由 `handleAiSendOrStop()` 改为直接 `sendAiMessage()`（loading 时入队而非停止）；`renderAiChat` 末尾恢复指示器。
