# 2026-07-08 工作日志

## 修复：对话日志 "Maximum call stack size exceeded" 错误

### 问题根因
当 AI 在 tool_call 中返回超长/复杂字符串（如大量 LaTeX 转义）到 `add_note` 后，`_rawLogs` 中的消息对象通过 `return m` 按引用返回，导致 `JSON.stringify(aiConvs)` 在 `saveData` 时遇到循环引用，抛出 "Maximum call stack size exceeded"。

### 修复内容

**文件：`js/ai.js`**
1. `safeJsonStringify` 函数 — 添加 `WeakSet` 循环引用检测，遇到循环引用返回 `[Circular]`
2. `callAiApi` 的 raw log — 始终创建消息对象的浅拷贝（`{ role, content, name }`），不再 `return m` 返回原始引用
3. `exportConvLog` 整体包裹 `try-catch`
4. `exportConvLog` 中 `JSON.stringify(m.content)` 改为 `safeJsonStringify(m.content)`
5. `add_note` 工具执行 — content 参数保留 LaTeX 定界符 `\[`,`\(`，只清理 `\n`；为笔记对象补上 `type:'note'` 和 `parentId:folderId`
6. `update_note` 工具执行 — content 参数只清理 `\n`
7. `move_note` 工具执行 — 改为设置 `note.parentId` 而非 `note.folderId`
8. 新增 `latexToHtml()` 函数，将常见 LaTeX 命令（sin/cos/frac/sqrt/lim/希腊字母/上下标等）转换为 HTML
9. `formatMarkdownBase` 中新增 `wrapBareLatex()` 兜底，自动给未包裹 \( \) 的裸 LaTeX 命令加行内数学定界符

**文件：`js/core.js`**
1. `saveData` 函数 — 包裹 `try-catch`，对 `study_ai_convs` 在序列化失败时自动清理 `_` 前缀字段重试，仍失败则降级保存

**文件：`js/notes.js`**
1. 新增 `repairCircularFolderRefs()`，修复文件夹自引用和循环链
2. `renderItem` 增加深度 50 上限和 `visited Set` 循环检测
3. `resolveNoteFolderPath` 增加空名称跳过、唯一 ID、自引用保护

**文件：`css/style.css`**
1. 新增 `.math-display`、`.math-inline`、`.math-frac`、`.math-sqrt` 等数学公式样式，根号使用伪元素 `√` 和顶线美化

**第五次修复（23:38-07-09）：parseSingleToolCall 改用 JSON.parse 解决双反斜杠问题**
- 根因：`parseSingleToolCall` 手动提取 params 字段时不解析 JSON 转义，`\\Delta` 仍为 `\\Delta`（双反斜杠），导致 `latexToHtml` 找不到匹配、`wrapBareLatex` 也无法包裹
- 修复：用 `JSON.parse(paramsJson)` 替换手动提取，`\\Delta` → `\Delta`（单反斜杠），后续 LaTeX 渲染正常
- 同时修正 `wrapBareLatexSegment` 的替换字符串：之前错误地产出 `\\(...\\)`（双反斜杠定界符），改为正确的 `\\(...\\)`（单反斜杠定界符）；并收紧尾随和正则，避免跨命令/跨括号过度贪婪匹配
