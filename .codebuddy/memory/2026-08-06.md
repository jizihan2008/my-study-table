## 任务线 DAG 手动画布 + AI 摆位 v0.2.7

用户需求：允许 AI 设置任务节点在画布上的位置（GTNH 手动画布风格）。四轮澄清确认：
1. **p1 位置设置方式**：工具参数指定坐标（quest_create/quest_update 增 `pos:{x,y}`）
2. **p2 布局模式**：整章手动模式——本章节内任一任务有 pos 即整章切手动布局
3. **p3 用户手动拖拽**：图头部有「拖拽」切换按钮，开启后可拖节点（默认关闭，点击正常打开详情）
4. **p4 连线依据**：箭头跟随 deps（位置自由，连线仍按 deps 自动生成）

### 实现
- **taskline.js 数据层**：quest 增 `pos:{x,y}`（画布绝对坐标，节点左上角，非负整数）。`tlAddQuest` 增 pos 参数（校验 number+isFinite 才存）；`tlUpdateQuest` 增 patch.pos（对象校验存 / null 或 false 删除回退自动布局）。
- **taskline.js 布局**：`tlLayoutGraph` 开头检测 `quests.some(q=>q.pos)` → 手动模式调新函数 `tlLayoutGraphManual(quests, extList, all)`。手动模式：有 pos 按坐标放（+TL_PAD 偏移）；外部占位节点放最左侧列；无 pos 任务排默认区（右下依次横向）；箭头仍按 deps 自动连（含 ext 虚线）。返回加 `manual` 字段（自动 false / 手动 true）。
- **taskline.js 拖拽**：全局 `tlDragMode` 状态；图头部 `.tl-graph-actions` 加「拖拽/拖拽中」切换按钮（`tlToggleDragMode` 调 renderTaskLine，图标 move/hand）；拖拽开启时节点加 `.tl-node-draggable` 类 + `onmousedown="return tlNodeDragStart(event,id)"`（替换 onclick，防止误触发详情）；`tlNodeDragStart` 用 mousemove/mouseup，区分点击（无移动→开详情）与拖动（写入 pos = 新坐标 - TL_PAD，`tlUpdateQuest({pos})` 后 renderTaskLine 重算连线）。
- **ai-tools.js**：quest_create/quest_update description 加 pos 说明（设了即整章手动布局/未设自动排默认区/箭头仍按 deps）；params 增 `pos: '画布坐标 {x,y} object 可选'`；执行端透传 pos；quest_get 详情加 `📍 画布位置：(x, y)`。
- **css**：`.tl-node-draggable`（grab/grabbing 光标、拖拽高亮）、`.tl-graph-actions .notes-undo-btn.active`（按钮激活态）。
- **版本**：package.json 0.2.6→**0.2.7**；index.html taskline.js r5→`20260806-r7`、ai-tools.js r3→r4、style.css r21→r22。node --check 通过、lint 0 错误。

## 日报修复：昨日习惯 + 复习笔记"未命名/第0轮" v0.2.8
用户反馈：(1) 早间日报应看到**昨天**的习惯完成情况并注明；(2) AI 日报里的复习笔记全是"未命名"和"第0轮"。
### 根因（重要 bug）
- **`getNotesDueForReview()` 返回的是 `{note, reviewCount, nextReviewDate}` 包装对象数组**（notes.js 1136-1157），但 settings.js 两个数据收集函数与 ai-tools.js 的 get_review_status / buildToolsSystemPrompt **误把包装对象当笔记本身用**（`n.title`/`n._reviewHistory`/`n._lastReviewDate`/`n._reviewDays` 全 undefined）→ 标题恒"未命名"、reviewCount 恒 0→"第0轮"、逾期天数恒 0。**必须解包 `d.note`**。
- `_lastReviewDate`/`_reviewDays` 字段在 notes.js 中**不存在**（废弃字段），逾期天数应基于 `nextReviewDate < todayStr` 计算（`toLocalDateStr(d.nextReviewDate)` 与 todayStr 比较，差的天数 = overdueDays）。
- **`calcHabitStreak` 函数不存在**（habits.js 只有 `calcStreak(habit)` 返回 `{streak, bestStreak, todayCount, todayMet, target}`）→ settings.js 里 `calcHabitStreak ? calcHabitStreak(habit) : 0` 恒为 0。改为 `calcStreak(habit).streak`。
- 早间日报习惯数据原用 `todayStr`（今天），早间回顾的应是昨天 → 改 `yesterdayStr`。
### 修复内容
- **settings.js `collectDailyReportData`**（早间）：reviewDueNotes 解包 `d.note` + 正确 overdueDays；habitsOverview 改昨日（字段 dayCount/dayMet）+ streak 用 calcStreak；habitsDoneToday → **habitsDoneYesterday**；早间 prompt【今日习惯】→【昨日习惯】（昨日完成情况）并注明，方向 7 改"昨天"；复习轮次显示 `reviewCount===0 ? '📌 首次待复习' : '第'+(count+1)+'轮'`。
- **settings.js `collectEveningReportData`**（晚间）：同样解包 reviewDueNotes + 逾期计算 + streak 修复（晚间习惯保持今日 todayStr 语义）；晚间 prompt 复习轮次显示同样修正。
- **ai-tools.js**：`get_review_status` 与 `buildToolsSystemPrompt` 复习段解包 `d.note`，轮次显示 `第${count+1}轮`。
- **版本**：package.json 0.2.7→**0.2.8**；index.html settings.js r11→`20260806-r12`、ai-tools.js r3→`20260806-r4`。node --check 通过、lint 0。
- 待办：重启 Electron 实测早间日报显示昨日习惯 + 复习笔记正确标题/轮次。
