## 修复：CodeBuddy CLI 输出乱码 + agent 异常退出 code=1（main.js）
- **现象**：启动 agent 时日志乱码「������̫����」，随后 agent code=1 退出。
- **根因（两个）**：
  1. Windows 下 `spawn(codebuddy.cmd, args, { shell: true })` 走 cmd.exe 二次解析，长 prompt 中的双引号（JSON 摘要）和 `--allowedTools Read Edit Write` 等含空格参数被破坏 → CLI 参数错乱报错退出 code=1。
  2. `String(d)` 强制按 UTF-8 解码子进程输出，Windows 下 GBK 内容全变 U+FFFD 乱码，真实错误信息不可读。
- **修复（main.js）**：
  1. 新增 `resolveCliEntry(cliPath)`：读取 .cmd/.bat 包装脚本内容，正则提取真实 JS 入口路径（`%dp0%\node_modules\@tencent-ai\codebuddy-code\bin\xxx.js`），返回 `{script}`；失败返回 null。
  2. `codebuddy:run` 优先 `spawn(process.execPath, [script, ...args], { env: {..., ELECTRON_RUN_AS_NODE:'1'} })` —— **Electron 的 process.execPath 是 electron.exe，必须加 `ELECTRON_RUN_AS_NODE=1` 才会以纯 Node 模式执行脚本**（否则会启动 Electron 窗口）。绕开 cmd.exe 后：无参数转义问题、输出纯 UTF-8。
  3. 回退方案：`cmd.exe /d /s /c <quoteCmdArgs>`（参数逐个双引号包裹 + `"`→`\"`）。
  4. 新增 `createStreamDecoder()`：**首段缓冲 1KB 探测编码**——用 `TextDecoder('utf-8',{fatal:true})` 严格解码去掉末尾 3 字节的探针，失败则整体切 `TextDecoder('gb18030')`；探测后必须 `pending = Buffer.alloc(0)` 清空（否则 flush 重复解码前 1KB）；`flush()` 兜底。

- **渲染端**：codegen.js 失败卡片新增 `cgAuthHint`——错误含 login/auth/api key/未登录/未授权/登录/授权/token 时提示「终端运行 codebuddy 登录，或到设置→AI 设置配置 API Key」。版本 bump 到 r3。
- **验证**：单元测试 6/6 通过（utf8 短/长文本、GBK 自动切换无乱码、UTF-8 分块边界无损、.cmd 解析、非 cmd 返回 null），测试脚本已删；main.js/codegen.js `node --check` + 0 lint。
- **经验**：GBK 编码的"失败"=`CA A7 B0 DC`（此前误记为 C6F4 B4ED 那是"启错"）。Electron 内置 Node 为 full ICU，TextDecoder 支持 gb18030；本机 node 也支持。
- **二次修复（真正的根因）**：修复后仍乱码 + code=1。在本机实测 `C:\Users\纪子涵\AppData\Roaming\npm\codebuddy.cmd`：**npm 全局 bin 入口是 `node_modules\@tencent-ai\codebuddy-code\bin\codebuddy`（无 .js 扩展名，shebang `#!/usr/bin/env node` 的 JS 脚本）**，而 `resolveCliEntry` 旧正则要求 `.js` 结尾 → 解析失败返回 null → 走了 cmd.exe 回退分支 → 长 prompt 引号被 cmd 破坏 → code=1 + GBK 乱码。修复：`resolveCliEntry` 改为提取 .cmd 中所有双引号包裹路径，从后往前找含 `node_modules` 且以 `[\\/]bin[\\/]<name>` 或 `.js/.mjs/.cjs` 结尾的入口，替换 `%dp0%` 并校验存在。
- **实测验证（本机）**：修复后解析真实 codebuddy.cmd → 正确得 `...\bin\codebuddy`；用项目 `node_modules\electron\dist\electron.exe` + `ELECTRON_RUN_AS_NODE=1` 完整跑 `-p hello --output-format stream-json --add-dir <项目根> --allowedTools "Read Edit Write" --dangerously-skip-permissions`，**exit=0，stream-json 正常输出，无乱码**，初始化消息显示 `apiKeySource: www.codebuddy.ai`（用户 CLI 已登录）、`permissionMode: bypassPermissions`。注意：npm 包名/路径含非 ASCII（纪子涵）不影响 spawn；**cwd 无效时 spawn 报 ENOENT 且错误信息指向 exe 路径，易误判**（应先确认 cwd 存在）。临时测试脚本已删。

## 修复：最后回复被 CLI meta 文本污染（codegen.js r10）

- **验证**：node --check + 0 lint；黑盒 6/6 PASS（meta 启动/完成识别、正常文本不误判、最后回复=AI正文、摘要 JSON 剥离、不含 meta）。index.html bump r10。需完全重启 Electron 生效。
