## 修复：手机端 4 个 AI 日志传不上云端（2026-08-14，sync-logs.js r4）

- **现象**：手机 PWA 本地有 4 个 AI 对话日志，点「上传全部」后云端仍只有 2 个（那 2 个是桌面端 Electron 传的）。
- **根因**：手机 PWA 的 WebView/浏览器**不支持 `CompressionStream`/`DecompressionStream` 或 `Blob.stream()`** → `_gzipB64` 抛异常 → `_packItem` 的 `catch(e){continue}` **静默跳过全部 item** → 手机端 0 上传。
- **修复**（sync-logs.js r4）：
  1. `_gzipB64`/`_gzipDecode` 改为 `_encodePayload`/`_decodePayload`：检测 `CompressionStream && Blob.prototype.stream` 可用才用 gzip；否则**降级 plain base64**（`btoa(unescape(encodeURIComponent(text)))`，wrap `c:'plain'`），任何环境都能传；解码侧 `c==='plain'` 走 `decodeURIComponent(escape(atob(d)))`。降级体积更大 → 更早触发分片，仍可增量。
  2. `uploadAll()` 增强结果反馈：统计 uploaded/skipped/failed + reasons，`console.warn` 输出明细，`showMiniToast` 弹「上传完成：成功 X，跳过 Y，失败 Z（原因）」（失败红色），`_emitProgress` 置 error/done。
  3. `_packItem` 压缩失败不再静默：`_flushLogs` 与 `uploadAll` 均 `console.warn` 具体 kind/itemId/错误。
- 版本号 sync-logs.js → `20260814-r4`。未提交未推送。

## 重大修复：跨设备 `_pruneRemote` 灾难性误删（2026-08-14，sync-logs.js r5）

- **现象升级**：电脑端（Electron 支持 gzip）也「7 条只传 3 条，全部显示已同步」。推翻压缩不兼容是唯一根因。
- **真根因**：`_pruneRemote`（TTL 清理）用**本机提取集合**（retainedBase）判断云端行是否保留 → **跨设备灾难**：手机本地 4 会话、电脑 7 会话，手机一同步就删掉云端"本地没有"的会话（反之亦然）。删除后本地 ts/hash 仍在 → 再次「上传全部」被 hash-skip 跳过 → 云端永远缺条目，本地却显示"已同步"。
- **修复**（sync-logs.js r5）：
  1. **禁用 `_flushLogs` 中 `_pruneRemote` 调用**（注释说明原因；云端 TTL 清理改由云端定时任务，前端不再做任何删除）。
  2. **`uploadAll` 强制全传**：`_uploadPiece(session, piece, force=true)` 跳过 hash 增量判断直接 upsert——「上传全部」语义=真正全部推到云端，自愈被误删/外部清理的行。自动同步（`_flushLogs`）仍走增量（force=false）。
- 版本号 sync-logs.js → `20260814-r5`。未提交未推送。

## 修复：手机添加计时记录不同步到电脑（2026-08-14，sync.js r3 客户端时钟偏差）

- **现象**：手机手动添加计时记录 → 电脑收不到。写点已修（saveTimerRecords→saveData），写链正常。
- **真根因（LWW 时钟偏差）**：sync.js `_uploadKey` 上传时 `updated_at = new Date().toISOString()`（**客户端本地时间**）写入云端；电脑 `_pullAll` 判定「云端更新」用 `remoteTs > localTs`（本机时间）。**手机时钟比电脑慢 → 云端 updated_at 早于电脑 localTs → 电脑判定"云端不新" → 永不拉取**。这是多设备 LWW 的经典时钟偏差坑（手机时钟常不准）。
- **修复**（sync.js r3）：
  1. `_uploadKey`：upsert **不传 updated_at**（数据库 `default now()` = 服务器时间），`.select('updated_at').single()` 返回真实写入值，写回 `_setRemoteTs/_setLocalTs`；select 抛错时用客户端时间兜底并视为成功（不误入 outbox）。
  2. `_flushOutbox` 补传同样不传 updated_at（服务器 now()），避免 outbox 旧客户端时间戳污染 LWW。
  - 效果：云端时间戳恒为服务器时间，两端 localTs 均锚定服务器时间，时钟偏差不再影响"谁新用谁"。

- **根因**：AI 常用 tree 命令风格 `├── name`（**双横线** `──`），而树形字符正则 `/^([│| ]*)([├└])─\s*(.*)$/` 只吃**一个** `─`，`\s*` 不能匹配第二个 `─`（U+2500 非空白）→ `(.*)` 从第二个横线开始捕获 → 节点名残留 `─ `。单横线（此前 AI 输出）正常，所以早期测试未暴露。
