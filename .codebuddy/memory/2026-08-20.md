# 2026-08-20

## 修复：教材系统目录页码识别（印刷页码误当 PDF 物理页码）

**Bug**：教材导入走「原书目录页解析」（`parseContentsFromToc`）时，目录行尾数字是**印刷页码**（书页上印的页码），被直接当作 `page` 存进章节树，随后 `splitChaptersAtLevel` 把它当 **PDF 物理页码**（1 起始，从封面算）消费，导致章节跳转/正文缓存/页码显示整体偏移了封面/扉页/前言/目录等前置页数。而 outline（书签）路径的 `resolveOutlineDestPage` 返回 `getPageIndex+1` 是物理页码，两者语义不一致。

**修复**（`js/books-pdf.js` + `js/books.js`）：
- 新增 `_extractTocNum(title)`：从标题提取章节编号（`1`/`1.1`/`2.3.4`，兼容 `Chapter 1` 前缀）。
- 新增 `calibrateTocPagesByOutline(tocTree, outline, pageCount)`：按章节编号匹配 outline 物理页码与 toc 印刷页码，算 `offset = 物理 - 印刷`，取众数，再把整棵 toc 树的 `page` 统一 `+= offset`（clamp 到 pageCount）。
- `parseContentsFromToc` 增加第三参数 `outline`，在 return 前调用校准；两处调用点（bkImportBook / bkReimportBook）传入 `parsed.outline`。

**局限**：仅对「有书签（outline）」的 PDF 生效；无书签 PDF 保持原行为。旧书需重新导入才会修正。
