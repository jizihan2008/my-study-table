`CODEBUDDY_API_KEY`+`CODEBUDDY_INTERNET_ENVIRONMENT=internal` 环境变量；打包版（app.isPackaged）源码在 asar 须先 `src:export-snapshot` 到 `~/.my-study-table/source-snapshot/` 再 `--add-dir`；CLI 探测优先用户配置 `study_codebuddy_cli_path`。**Windows 运行必须绕开 cmd.exe**：用 `resolveCliEntry` 解析 .cmd 真实脚本入口——**npm 全局 bin 入口可能无 .js 扩展名**（如 `node_modules\@tencent-ai\codebuddy-code\bin\codebuddy`，是带 `#!/usr/bin/env node` shebang 的 JS），正则需匹配 `node_modules[\\/].*[\\/]bin[\\/]<name>` 结尾；然后 `spawn(process.execPath,[script,...],{env:{ELECTRON_RUN_AS_NODE:'1'}})`（Electron 的 execPath 是 electron.exe，必须加该变量才以纯 Node 正常、无乱码。**登录检测**：CLI 无非交互 login/status 子命令、凭据不在明文文件 → 跑极简 `-p hi` 任务，输出含 `Authentication required|Please use /login` 即未登录，12s 超时 kill 判已登录（渲染端 `ensureLoginCheck` 带 5min 缓存+并发防重，`cgLoginUsable` 判定已配置 - **好友系统架构**（2026-08-05，v0.3.0）：联网好友系统基于 **Supabase**（PostgreSQL+Auth+RLS+Realtime）。建表脚本 `supabase/schema.sql`（profiles/friend_groups/friendships/study_stats/activities/conversations/messages，全 RLS + `handle_new_user` 触发器 + `alter publication supabase_realtime`）。前端 `js/friends.js`（配置 key `study_friends_config`、`getSupabaseClient` 单例用 window.supabase UMD 位于 `lib/supabase/supabase.js`、认证/分组/好友/聚合统计 `computeDailyStats`+`syncStudyStats`/动态流/在线心跳）+ `js/friends-chat.js`（会话 `friendsConvPair` 规范化、消息/未读/Realtime 订阅/资料卡）。加载顺序 updater.js 后：supabase.js → friends.js → friends-chat.js。侧边栏「好友」nav id=friends、`section-friends` 内 `#friendsApp`、设置页「好友」tab(settingsPanelFriends, load/saveFriendsSettings)。**隐私红线**：只同步聚合统计（打卡/专注毫秒/完成数/习惯次数/连续天数），绝不上传具体待办/笔记内容，靠 RLS `is_friend()` 保证仅本人+好友可见。使用前提：Supabase 控制台执行 schema.sql；Auth→Email 建议关 "Confirm email"。SDK 经 `npm.cmd install @supabase/supabase-js@2 --no-save` 后拷 UMD 到 lib/supabase/。**坑**：订阅回调里动态流更新用 `renderFriendsFeedView` 手动 innerHTML，勿调不存在的 renderFriendsFeed。
- **AI 树状对话架构**（2026-08-03）：AI 聊天已从「线性消息数组 + `_candidates` 平级候选」重构为「树状分支对话」。数据模型：`conv.tree`（节点字典，root 为 `{role:'root'}`）+ `conv.activePath`（根→当前节点路径）+ **`conv.messages` 保留为活跃路径的扁平缓存视图**（由树引擎同步，外部读路径零改动）。核心 API 在 `js/ai-tree.js`：`ensureTree`/`migrateConvToTree`/`appendMessage`/`createBranch`/`switchBranch`/`recomputeMessages`/`resetConvTree`/`trimConvMessages`/`branchInfoAt`/`siblingBranchCount`/`siblingNodeIds`。**写消息一律走 `appendMessage(conv,msg)`，禁止直接 `conv.messages.push`**（会破坏树同步）。候选/重新生成 = user 节点下的兄弟分支；「换一条」按钮调 `regenerateAiMessage(nodeId)`。渲染在 `ai-render.js` 遍历 `activePathNodes`；工具栏「分支树」按钮调出树形导航浮层（`toggleAiTreePanel`/`switchToTreeBranch`）。脚本加载顺序：`ai-utils.js` → `ai-tree.js` → `ai-conv.js` → `ai-attach.js` → `ai-render.js` → `ai-tools.js` → `ai-search.js` → `ai-api.js` → `ai-send.js`。
- **AI 模块拆分**（2026-07-18）：`js/ai.js` 已拆分为 8 个模块（后增 `ai-tree.js` 为 9 个），按依赖顺序在 `index.html` 中加载（见上条）。备份在 `js/ai_backup_20260718.js`。
- **AI tool_call 参数解析**：`js/ai-tools.js` 中的 `parseSingleToolCall` 必须使用 `JSON.parse()` 解析 `params` 对象，而不是手动正则提取字段。手动提取不会解码 JSON 转义，会导致 `\\Delta` 等内容保持双反斜杠状态，LaTeX 渲染失败。
- **笔记数据模型**：AI 创建的笔记对象必须包含 `type: 'note'` 和 `parentId`（而非旧的 `folderId`），否则 `js/notes.js` 的渲染/查找函数无法识别。
- **文件夹循环引用保护**：`js/notes.js` 的 `renderItem` 必须限制递归深度并使用 `visited Set` 检测循环；`resolveNoteFolderPath` 需避免 self-parent。
- **AI 记忆系统用户画像**：`memory.profileText` 是单段自由文本，由 AI 每日自动生成全方位总结。不再是独立的分段字段 (nickname/identity/goals/style)。已有旧数据（分段格式）在 `loadAiMemory()` 中自动迁移合并为一段文字。
- **液态玻璃折射**（2026-07-22 r23）：拆分为三个独立控制——`glassCurve`（弯曲程度→SVG displacement scale 0~60px）、`glassDeflect`（偏折程度→edge zone 0~0.4）、`glassGlow`（顶层辉光→`--glass-glow` CSS 变量 0~1）。`js/liquid-glass.js` 的 `updateLiquidGlass(scale, edgeRatio)` 支持仅更新单个参数（undefined 跳过）。`settings.js` 中 `applyGlassCurve/Deflect/Glow` 三个函数替代旧 `applyGlassRefract`。CSS `--glass-glow` 同时控制 opacity + brightness。仅 Chromium 支持 `backdrop-filter: url()`。
- **预设→自定义切换规则**（2026-07-22）：`js/settings.js` 中 `switchToCustomMode(cfg)` 是唯一切换到自定义模式的入口。所有设置修改 handler 必须先调用 `switchToCustomMode(cfg)`（复制预设全部有效值到 cfg），再修改具体属性值，再 save。禁止内联 `cfg.preset = 'custom'`。
- **版本发布策略·方案 B**（2026-08-02 确认）：一律使用三位 semver，**MAJOR 位表示项目阶段**（阶段一=`1.x.y`、阶段二=`2.x.y`…），MINOR=向后兼容新功能，PATCH=bug 修复。版本号全局唯一、单调递增，永不复用。当前 `0.1.x` 属初始开发迭代期，正式进入阶段一以发布 `1.0.0` 为标志。禁止使用四位版本号（如 `0.1.11.1`）——已实测验证 npm semver 解析为 null、`gt` 比较抛 `Invalid Version`，`electron-updater/out/AppUpdater.js` `isUpdateAvailable` 对非法版本抛 `ERR_UPDATER_INVALID_VERSION`，构建阶段 electron-builder 同样校验 package.json version。

- **GitHub 发布经验·exe 补传**（2026-08-04 更新）：80MB exe 经 electron-builder `npm run publish` 上传极易超时中断（0.1.11、0.1.13 均发生），现象是 release 只有 blockmap + latest.yml 而无 exe。**已验证的修复命令**（无需代理）：先取 release id `curl https://api.github.com/repos/jizihan2008/my-study-table/releases/tags/v0.1.13`，再 `POST https://uploads.github.com/repos/jizihan2008/my-study-table/releases/{id}/assets?name=My-Study-Table-Setup-0.1.13.exe`，Header `Authorization: Bearer <GH_TOKEN>` + `Content-Type: application/octet-stream`，body `--data-binary @本地exe`。**资产名必须用连字符版本**（`My-Study-Table-Setup-0.1.13.exe`，与 latest.yml 的 url 字段一致）。上传后验证：release 资产含 exe+blockmap+latest.yml，下载 URL 跟 302 后返回 200。token 环境变量/gh CLI/electron-builder 缓存均不持久，每次补传需用户重新提供 GH_TOKEN；token 明文绝不写入记忆文件。

### 应用运行约定
- 修改 `js/` 或 `css/` 文件后，**必须完全重启 Electron 应用**才能加载新代码；窗口刷新不足以重新加载主进程注入的脚本。
