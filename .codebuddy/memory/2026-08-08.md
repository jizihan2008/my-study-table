## 任务线箭头优化 2：重叠轴取重叠区间中点 v0.2.14
用户反馈："不一定是中点"——锚点不应固定取节点边的中心，应取边上最接近对方的位置。
- **taskline.js** `tlEdgeAnchorPoints` 增强：计算两矩形在垂直轴的重叠区间 `yOverlap` / 水平轴 `xOverlap`；当主导方向为水平（连左右边）且两节点在垂直方向有重叠时，锚点 y1/y2 取**重叠区间的中点**（`(max(a.y,b.y)+min(a.y+a.h,b.y+b.h))/2`），否则取各自中心；垂直主导同理取水平重叠区间中点。即连线在重叠处进出，从最近位置对接。

## 任务线箭头优化 3：投影+clamp 最近点锚点 v0.2.15
用户反馈：有时仍退化为中点。旧算法取"重叠区间中点"——当重叠区间对称时仍落在中心附近，视觉上像中点。
- **taskline.js** `tlEdgeAnchorPoints` 重写：
  - **主导方向用间隙法**：`gapX = max(a.x,b.x)-min(a.x+a.w,b.x+b.w)`（重叠为负，越小越贴），`gapX<=gapY` 走水平连接（左右边），否则垂直连接（上下边）——比旧的归一化中心距离更准确。
  - **锚点用投影+clamp**：水平连接时把对方中心 y 投影到己方垂直范围（`clamp(bcy, a.y, a.y+a.h)`），得到边上真正离对方最近的点；垂直连接时把对方中心 x 投影到己方水平范围。不再退化为固定中心点（除非两中心投影恰好重合）。
- 版本：package.json 0.2.14→**0.2.15**；index.html taskline.js r13→`20260808-r14`。node --check 通过、lint 0。
- 待办：重启 Electron 实测——错位摆放节点时箭头从边上最近点进出（不居中、不穿框）。

## 任务线箭头优化 4：重叠取靠近对方点 / 无重叠取中点 v0.2.16
用户反馈：现在都在角上。原因：v0.2.15 的"投影+clamp 到整个边范围"在两节点垂直/水平完全不重叠时，clamp 把锚点推到自己角的坐标 → 角到角连线。
- **taskline.js** `tlEdgeAnchorPoints` 再修：主导方向仍用间隙法（gapX<=gapY 水平）；锚点策略分两种情况——**有重叠**（yOverlap>0 或 xOverlap>0）时锚点取"重叠区间内靠近对方中心"（`clamp(bcy, yLo, yHi)`，yLo=重叠上界、yHi=重叠下界），既非整体中心也不贴角；**无重叠**时用各自在连接轴上的中点（acy/bcy 或 acx/bcx），避免角到角。
- 版本：package.json 0.2.15→**0.2.16**；index.html taskline.js r14→`20260808-r15`。node --check 通过、lint 0。
- 待办：重启 Electron 实测——上下错位（垂直重叠）节点在重叠区靠近对方处连接；斜角不重叠节点用中点水平/垂直接线。
