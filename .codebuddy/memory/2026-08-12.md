## 修复：教材三级导航空白 + Realtime 订阅报错 + dev-server MIME（2026-08-12）

**根因与修复：**
1. **三级导航空白（css/style.css）**：移动端 `#booksApp` 是 `flex-direction:column`，三个子项（.bk-shelf/.bk-toc/.bk-main）原设 `height:100%; flex-shrink:0`，多个 `height:100%` 子项在 flex column 中总高 300% 叠加被 `overflow:hidden` 裁剪——只有第一个（书架）在顶部可见，后面的（目录/内容）被挤出可视区。**修复**：改为 `flex:1 1 auto; min-height:0`（显示项撑满剩余、隐藏项 display:none 不占位）。这是三级导航空白的关键。
2. **Realtime 订阅报错（js/sync.js `_subscribe`）**：`_subscribe` 被多处在登录时重复触发（_init/_doSyncAfterLogin/登录回调）；且 `c.channel('mst-user-data')` 对同名 channel 会复用已 subscribe 的对象，再 `.on('postgres_changes')` 即报错。**修复**：加 `_subscribing` 并发锁（重复调用直接 return）+ 每次订阅前用 `await c.removeChannel(realtimeChannel)` 彻底移除旧 channel（不能只 unsubscribe）。sync.js 版本 `r1→r2`。
3. **dev-server MIME（dev-server.js）**：mime 映射缺 `.mjs`，pdf.min.mjs 被当 octet-stream。**修复**：加 `'.mjs': 'application/javascript; charset=utf-8'`。GitHub Pages 不受影响，仅本地预览。改后需重启 dev-server（Stop-Process 8080 占用 PID → Start-Process node dev-server.js）。

## 方案2：profiles 最小公开视图（供插件市场作者展示）

- 问题：收紧 profiles RLS（`using(auth.role()='authenticated')`）后，**未登录用户无法读 profiles**，导致插件市场 `_enrichAuthorNames`（store.js 第146行查 profiles 补作者名）失效，author_name 为空的插件对未登录用户显示"匿名"。
- 方案2（用户确认）：新建**最小公开视图** `profiles_public`，只暴露 `id, nickname, username` 三列，GRANT select 给 `anon` 和 `authenticated`。**RLS 是行级非列级，无法用策略限制列，故用视图实现列级最小暴露**。
- 改动：
  - `supabase/schema.sql`：profiles RLS 策略后新增 `drop view if exists profiles_public` + `create view profiles_public with (security_invoker=true) as select id,nickname,username from profiles` + `revoke all from anon,authenticated` + `grant select to anon,authenticated`。（`security_invoker=true` 让视图继承基表 RLS，需基表行对调用者可见才返回——对 anon 不可见，但 GRANT 视图本身可读；注意此视图基于 profiles，而 profiles 对 anon 是 RLS 不可见的，实际 anon 读视图也会因 security_invoker 受基表 RLS 限制而返回空！见下坑）
  - `js/store.js`：`_enrichAuthorNames` 从 `from('profiles')` 改为 `from('profiles_public')`。
  - `index.html`：store.js `r14→r15`。
- **坑（重要）**：`security_invoker=true` 视图会强制基表 RLS，而 profiles 对 anon 的 RLS 是拒绝的，所以 anon 读 `profiles_public` **仍返回 0 行**（视图空）。要让 anon 能读作者名，应**不用 security_invoker**（默认 `security_definer`，以视图 owner=postgres 权限读基表，绕过 profiles 的 RLS）。若发现 anon 读视图仍空，需把 `with (security_invoker=true)` 改为 `with (security_definer=true)` 或直接省略（默认 definer）。**待验证**。

## 目录空白真正根因（重要，2026-08-12）

- 现象：GitHub Pages 上点书后目录空白，但本地 dev-server 一直正常。
- 根因：**localStorage 状态差异**。`bkApplyPanes()` 会按 `study_bk_panes_v1`（`_bkShelfHidden`/`_bkTocHidden`）给 `.bk-shelf`/`.bk-toc` 加 `.hidden`（display:none）。若用户曾在**桌面端隐藏过目录栏**（`_bkTocHidden=true` 持久化），移动端点书后 `.bk-toc` 被 `.hidden` 隐藏 → 空白。本地 localStorage 无此状态所以正常。
- 诊断方法（有效）：在浏览器控制台查 `document.getElementById('booksApp').dataset.bkview`、`getComputedStyle(bkToc).display`、`bkTocList.children.length`。本次诊断显示 `bkview=toc`、`bkToc display=none`、`bkTocList 子元素=106` → 数据对但 CSS 隐藏 → 定位到 hidden class。
- 修复（commit `dbec367`）：`bkApplyPanes()` 移动端分支（`bkIsMobileView()` 为真）强制 `classList.remove('hidden')` + return，不应用桌面隐藏状态。**移动端三级导航不使用可折叠侧栏，故跳过**。
- 教训：① 之前误判为 flex 高度叠加（flex:1 修复`0c24e76`其实对，但非根因）；② 用户浏览器可能通过不同 localStorage 产生线上/本地行为差异，排查时要区分；③ 诊断要让用户明确在**出问题的环境**（GitHub Pages）而非 localhost 执行。

## 本地信令方案：彻底摆脱 Supabase Realtime（2026-08-12 实施）

- 日志确凿：两端 `subscribe: SUBSCRIBED` 后，手机发的 ready 桌面收不到；随后 `socket closed: 1000`（Supabase Realtime WebSocket 被服务端关闭）。结论：**Supabase Realtime 服务当前异常**，信令广播无法跨客户端送达。用户 LocalSend 能通证明局域网 P2P 可行。
- **决定**：把 WebRTC PDF 传输信令从 Supabase Realtime 改为**本地 HTTP 信令服务器**（桌面 Electron 主进程起服务，手机通过局域网 IP 轮询）。
- **main.js**：新增本地信令服务器（纯 Node `http`，无新依赖）：
  - `POST /signal {code,event,payload}`：提交信令（手机→桌面），并把信令 `sendToRenderer('webrtc:signal-incoming')` 推给桌面渲染进程
  - `GET /signal/<code>?since=<seq>`：拉取增量信令（轮询用），含 CORS 头
  - `GET /ping`：健康检查
  - `signalQueues` Map 存每个 code 的信令队列（防内存增长，上限 500）
  - IPC：`webrtc:signal-start`（起服务，返回端口+局域网 IP）、`webrtc:signal-state`、`webrtc:signal-stop`
- **preload.js**：暴露 `webrtcSignalStart/State/Stop` + `onWebrtcSignalIncoming`（监听主进程推送的手机端信令）。
- **webrtc-send.js（桌面发送端）**：`startPair` 优先 `webrtcSignalStart` 起本地服务，`sndSigBase='http://<ip>:<port>'`，`_sigPost(code,event,payload)` 发信令；监听 `onWebrtcSignalIncoming` 处理 ready/answer/ice；`_createOffer` 的 offer/ice 走 `_sigPost`。非 Electron 降级回 Supabase Realtime。状态 `pairing` 带 `ip`/`port`。
- **webrtc-recv.js（手机接收端）**：`startReceive(code,{ip,port})` 走本地信令——`_rcvSigPost`（POST 信令）+ `_startSigPolling`（每 400ms 轮询 `GET /signal/<code>?since=`，处理 offer/ice）；answer/ice 走 `_rcvSigPost`。无 ip 降级回 Supabase。
- **books.js UI**：
  - 桌面端 `bkSendToPhone`：配对状态显示「本机 IP + 端口」供手机填写
  - 手机端 `bkReceiveFromPhone`：新增「桌面端 IP」「端口」输入框；`bkRecvConnect` 读取并传给 `startReceive(code,{ip,port})`
- 版本：webrtc-send/recv `r2→r4`、books.js `r13→r14`、index.html 更新。
- **注意**：需重启 Electron（main.js/preload.js 改动）才能生效；手机端 PWA 需部署后刷新。**尚未提交推送**。

## 本地信令回环 bug 修复（main.js + webrtc，2026-08-12）

- 用户反馈：接收端（localhost 网页版）只返回 `[webrtc-recv] 本地信令收到: ready`，然后没响应。

  - webrtc-send.js `_sigPost`：body 加 `from:'send'`
  - webrtc-recv.js `_rcvSigPost`：body 加 `from:'recv'`

## 修复「打开自动同步反复上传 1~15」（sync.js r17，commit 9c694a9）

**推送完成**：commit `9c694a9`（2 文件 +47/-29）并推送，`4a7746d..9c694a9 main -> main`（首次 push 握手失败重试成功）。

- **现象**：一打开自动同步就一直上传 1~15（15 个 key 反复上传不停止）。
- **根因**：`_pullAll` 两阶段拉取（先轻量元信息 syncRows，再对 needValueKeys 拉 value）。合并阶段对**不在 needValueKeys 的 key**（本地时间戳 ≥ 云端）`remoteRow` 是 undefined。旧代码 `remoteEmpty = !remoteRow || ...` 把 undefined 误判为「云端空」→ 走「云端空→上传本地」→ 每次 `_pullAll` 都把时间戳一致/本地不更新的 key 反复加入 dirtyKeys → 无限循环上传。
- **修复**：对 `remoteRow` undefined 的 key 不再误判云端空，改按时间戳判定：`localTs>remoteTs`（本地更新）→上传；`!localTs&&remoteTs`（备份保护）→上传；`localTs>=remoteTs`（一致/本地不更新）→**跳过**。拉到 value 的 key 保持「谁新用谁」，且 `localMs===remoteMs` 相等时跳过。
- 版本：sync.js `r16→r17`。
- **教训**：两阶段拉取（元信息+按需 value）时，不能用「没拉到 value」判定「云端无数据」；「云端是否有该记录」应以元信息 syncRows 为准，「云端值是否为空」才需 value。
