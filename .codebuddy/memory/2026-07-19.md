## 第三轮改动（2026-07-19 r4）

### 复习浮窗真正按内容自适应高度（第二次修复）
- **根因**：`.review-float` 使用 `display: flex; flex-direction: column`，flex 列布局会拉伸子元素导致无法按内容收缩
- `css/style.css`：
  - `.review-float`: 移除 `display: flex; flex-direction: column;` → 纯 block 布局，`overflow-y: auto` + `max-height: 75vh`，高度完全由内容决定
  - `.review-float-header`: 移除 `flex-shrink: 0`（不在 flex 上下文中），保留 `position: sticky; top: 0`
  - `.review-float-list`: 移除 `flex-shrink: 0`
- 效果：内容少矮、内容多高、超出 75vh 浮窗内滚动（标题栏 sticky 固定顶部）
- `index.html`: style.css → r4

## 第六轮改动（2026-07-19 r7）

### 复习浮窗自适应高度（第五次修复 — 徹底解決）
- **根因**：高度只在 `renderReviewFloat()` 的 setTimeout 中计算，但 `reviewFloatToggleExpand()` 直接切换 CSS class 不重算；prev/next 中 `switchTab('notes')` 与 setTimeout 竞态
- `js/today.js`：
  - 提取 `adjustReviewFloatHeight()` 为独立函数，含 `void float.offsetHeight` 强制回流
  - `renderReviewFloat()` 调用 `adjustReviewFloatHeight()`（80ms 延迟）
  - `reviewFloatToggleExpand()` 展开/收缩后调用 `adjustReviewFloatHeight()`（50ms 延迟）
  - `reviewFloatSelectCurrent()` 切标签页后调用 `adjustReviewFloatHeight()`（150ms 延迟，确保标签切换完成）
- `index.html`: today.js → r6

## 第七轮改动（2026-07-19 r7）

### 复习浮窗自适应高度（第六次 — 直接测量子元素）
- **根因**：`adjustReviewFloatHeight()` 通过解除 max-height → 读取 float.scrollHeight 再恢复，但绝对定位元素 `scrollHeight` 在 `height:auto` 下返回值不可靠，总是等于 viewport 高度导致固定为 75vh
- **新方案**：不操作 float 自身样式，直接测量子元素 `header.offsetHeight + list.scrollHeight` 得到内容真实高度
- 内容超出上限：`float.style.height = maxH` + `overflow-y: auto`（浮窗内滚动）
- 内容不超出：`float.style.height = contentH` + `overflow-y: hidden`（无需滚动条）
- `index.html`: today.js → r7
