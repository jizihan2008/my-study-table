### 修复 1：isInboxPathAllowed 误拒目录自身（v20260823）
- 现象：导入 JSONL 文件夹报「读取失败：路径不在允许范围内」。
- 根因：`main.js` 的 `isInboxPathAllowed` 用 `isPathInside(base,target)`（基于 `path.relative`），当传入路径**恰好等于白名单目录本身**时 `rel===''` → 返回 false。`qqchat:read-manifest` 传的 dir 就是用户刚选择的导出文件夹本身（`ensureInboxDirAllowed` 已加入白名单），被误拒。
- 修复：`isInboxPathAllowed` 增加 `abs === base ||` 判断放行目录自身。

### 修复 2：IndexedDB "connection is closing" 错误（v20260823-r1）
- 现象：导入过程中报 `Failed to execute 'transaction' on 'IDBDatabase': The database connection is closing.`
- 根因：`js/qq-chats.js` 的 `_open()` 把连接缓存在 `_dbPromise` 单例，但 14 处业务代码都调 `db.close()` 后**不重置 `_dbPromise`** → 下次 `_open()` 复用已关闭连接 → transaction 报错。
- 修复：新增 `_closeDb(db)`（`db.close()` + `_dbPromise = null`），全部 14 处 `db.close()` 替换为 `_closeDb(db)`。
- 验证：mock IDB 测试（test-qqchats-close.mjs，已删）连续 9 次操作 openCount(17)==closeCount(17)，无泄漏无报错。
- 版本：qq-chats.js→20260823-r1、service-worker→mst-v24。

### 修复 13：日报跳转后界面刷新丢滚动位置（v20260823-r13）
- 现象：用户反馈"有时候会刷新界面"，跳转后消息区滚动位置丢失。
- 根因：(1) `renderChatView` 第 1078 行**无条件** `scrollTop = scrollHeight`（每次渲染都滚到底）；(2) `locateAndJump` 用 `setTimeout(150ms)` 猜时间定位，但 `renderChatView` 是异步（先 `listChats` 再 `getMessages`），150ms 时 DOM 可能还没重建 → 定位失败 + 界面闪动。
- 修复（`js/inbox.js`）：

- 用户确认采纳方案 B：此前所有拉取路径统一 `_pullAll(true,true)` 强制拉取虽解决了 iPad 时钟偏差问题，但有隐患（每次全量拉 value 性能开销、forceRemote 可能覆盖本地未上传修改、自动同步频繁全量拉取）。

- **时钟污染自愈**：`_tsIsFuture(localTs, remoteMaxTs)`（本地时间戳比服务器参考快超 15 分钟 → 旧版污染残留）→ 本地时间不可信、云端权威覆盖校准，兼容旧数据平滑迁移。
- **调用点分流**：自动路径（`_debouncedPull` Realtime / `_init` 定时轮询 / `_doSyncAfterLogin` / init 登录态轮询）全部回退 `_pullAll(true,false)`；**仅 `manualSync` 保留 `_pullAll(true,true)` 强制拉取**（手动以云端为权威源）。
- 拉取判定顺序：本地空→拉；forceRemote→拉；dirty→保护本地上传；_tsIsFuture→拉取校准；remoteTs>localTs→拉；!localTs&&remoteTs→上传保护。
- `_uploadKey`：成功上传/超大 key 跳过均清 dirty（超大 key 用 remoteTs 兜底写 localTs，避免每轮重复入队）。
- 版本：sync.js→20260823-r6、service-worker→mst-v51。需重启 Electron + iPad 刷新 PWA（mst-v51）。

### 修复 29：iOS 磨砂效果不生效（v20260823-r1/liquid-glass）
- 现象：iOS（Safari PWA）开启液态玻璃后磨砂（blur）完全失效，面板只是半透明无模糊。
- 根因：`css/style.css` 中 `.sidebar/.card/.modal>div` 的 `backdrop-filter` 有两组规则——纯 blur「回退」（3433 行）+ `blur(...) url(#liquid-glass-filter)`（3441 行）。后者在级联上**总是覆盖**前者；而 `backdrop-filter: url()` 仅 Chromium 支持，WebKit（iOS Safari/iOS Chrome/iOS Edge）与 Firefox 遇到 url() 时**整条声明无效** → blur 磨砂也一起失效。
- 修复（`js/liquid-glass.js`）：
  - 新增 `isChromium` 检测（UA 含 `Chrome/<版本>` 且非 `CriOS|EdgiOS|FxiOS`），准确覆盖桌面 Chrome/Edge/Electron 与 iOS 浏览器。
  - 非 Chromium：`init()` 注入 `lg-blur-fallback` style（`backdrop-filter: blur(var(--glass-blur,16px)) saturate(1.4) !important`，带 `-webkit-` 前缀）覆盖带 url() 的规则；`updateLiquidGlass` 直接 return（跳过 SVG 折射注入）。
  - Chromium 逻辑完全不变（保留折射）。
- 版本：liquid-glass.js→20260823-r1、service-worker→mst-v52。需 iPad 刷新 PWA（mst-v52）验证；未提交推送（用户暂缓）。
