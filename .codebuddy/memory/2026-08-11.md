## 修复：部分邮件内容拉取不到 / 乱码

- 根因分析（`main.js` 自写 MIME 解析器 `extractMailText`）：
  1. **GBK/GB2312/Big5 中文编码**：原实现 `buf.toString(cs)`，Node Buffer 原生不支持 GBK/Big5，抛 `ERR_UNKNOWN_ENCODING` 被 catch 后按 utf8 解出乱码。
  2. **RFC 5322 折行 header**：原 `getHeaderVal` 正则 `[^\r\n]*` 不支持续行，boundary/charset 折行后取不到 → multipart 直接放弃、正文为空。
  3. **转发邮件 `message/rfc822`**：原解析器只处理 multipart/text，message/rfc822 完全忽略 → 转发正文为空。
  4. **解析器自身缺陷**：原 `walk(body, header)` 把去头后的 body 当含头节点递归，纯文本邮件正文全丢；且 multipart 首 part 被跳过。
- 修复方案：
  - 引入 `iconv-lite`（imapflow 的依赖，已扁平装顶层 node_modules，`require('iconv-lite')` 即可）解码中文编码，别名映射 GB2312→GBK、GB_2312→GBK、windows-936→GBK 等。
  - 重写 `extractMailText`：`parseNode(nodeBuf)` 只接收**完整节点**（header+body），递归时取自身头尾；multipart 用 boundary 分隔、结束边界 `--` 判断；`message/rfc822` 递归 `parseNode(body)`；text/ 解码后分流。
  - `getHeaderVal` 支持 `\r\n[ \t]` 续行并折叠回单行。
  - 健壮性：`decodeCharset` 内 try/catch（getIconv 调用在 try 内，防止解码器异常导致整封邮件丢正文）。
- 验证：临时 `_test_mail_parse.mjs` 9 个用例全过（纯文本/GBK+qp/折行boundary/rfc822转发/HTML-only/折行charset/base64/嵌套multipart/带附件），测后已删。
- 注意：改 main.js 需完全重启 Electron 生效。

- **三次修复（真正的根因，用户反馈"节点有了但无法右键"）**：`bkShowTermContextMenu` 中模式(b) 原本用 `const sel = window.getSelection(); if (!sel || sel.isCollapsed) return;` **无条件 return 退出整个函数**，而模式(c)（右键 `.bk-summary-node`）恰好放在模式(b) 之后——右键节点时无选中文字，被该 return 直接截断，模式(c) 永远执行不到。**修复**：把模式(b) 改为 `if (sel && !sel.isCollapsed) { ... return; }` 条件块，不再用裸 return，让无选中文字时自然落到模式(c)。books-ai.js 版本 `r4 → r5`。验证：DOM 模拟测试（stub getElementById/menu.classList/item.style/getSelection 无选中）6 项全 PASS（preventDefault/菜单 visible/original 显示/其他项隐藏/节点名记录/守卫含选择器）。
- **经验（本次教训）**：带多个分支的函数，把"无选中文字返回"写成裸 `return` 会截断后续分支；应改成条件块内 return。且模拟测试必须覆盖**分支可达性**（之前 _t_bkverify 只测了渲染与定位，没测右键菜单显示逻辑，故漏掉此 bug）。
- 临时脚本 `_t_bkctx_test.mjs` 仍在工作区根目录（delete_file 调用因超时被跳过），确认后手动删除。
- **样式修复（用户反馈"章节摘要字比原来大"）**：`.bk-summary-node` 未设置字号，内部 markdown（`.markdown-body`）继承页面默认字号（>13.5px），比原 `.bk-kb-summary-text`（13.5px）大。修复：`.bk-summary-node` 与 `.bk-summary-node .markdown-body` 均设 `font-size:13.5px; line-height:1.8; color:var(--text)`，并紧凑内部 ul/ol/li/p/h 边距。仅改 css/style.css，重启生效。
- **样式微调（用户反馈）**：节点间竖向间隔取消（`.bk-summary-nodes` gap 6px→0）；节点高度调小（`.bk-summary-node` padding 8px 10px→2px 10px、内部 li/p margin 2px 0→0）。
- **摘要质量下降修复（用户反馈"加了右键原文功能后 AI 摘要细节下降"）**：根因 = 输出 token 预算被 `summaryNodes` 抢占。`callAiApi` max_tokens 默认仅 2048（非 Kimi），新增 summaryNodes 后输出量接近翻倍（每条 text 重复摘要 + src 逐字摘录原文 1~2 句），模型被迫压缩 summary。**三重修复**（books-kb.js，版本 r4→r6）：
  1. **src 改短**：prompt 改为"逐字摘录 8~25 字简短片段（含独特关键词的短语/半句），勿摘录过长整句"——定位仍够用（_bkNormText 归一化+模糊匹配），token 大省；
  2. **提高输出上限**：`bkBuildChapterKb`/`bkBuildChapterSummary` 调用 callAiApi 时传 `kbCfg = {...c, maxTokens: Math.max(c.maxTokens || 0, 8192)}`（尊重用户已配更高值），构建长输出不再受限；
  3. **prompt 声明优先级**：规则改为"⚠️ summary 是核心交付物，必须 250-450 字完整详细，禁止为 summaryNodes 压缩/简化"，并重排规则编号（6 节点规范 / 7 优先级 / 8 summaryNodes / 9 伪代码）。
- 经验：往 prompt 加输出字段会挤占固定 max_tokens 下其他字段的质量，凡增加输出结构应同步提高 max_tokens 或缩减字段体积。

## 功能：摘要节点 src 改为 PDF 页码 + 内嵌 PDF 阅读器跳页

- 需求：src 改为 AI 回复每个节点对应的 **PDF 页码**（非书的页码），点击「显示原书原文」自动打开 PDF 并翻到那一页。
- 背景确认：`chapter.startPage/endPage` 本就是 1 起始的 PDF 物理页码（`resolveOutlineDestPage` 返回 pageIndex+1，AI 切分也用逻辑页码），与 pdf.js `getPage(N)` 一致；应用此前**没有 PDF 阅读器**（pdf.js 仅用于 `parsePdfFile` 提取文本），故需新建内嵌阅读器。
- 改动：
  - `js/books-pdf.js`：新增 `getChapterTextWithPages(cache, chapter)`——绕过 `chapterTexts` 纯文本缓存，按 `cache.pages` 逐页拼接并每页前插「〔第 N 页〕」标记（`'〔第 ' + i + ' 页〕' + t`，空页跳过）；新增包装 `bkGetChapterTextWithPages(chapter)`（基于 bkEnsureTextCache）。
  - `js/books-kb.js`：`_bkBuildChapterCore` 构建文本改用 `bkGetChapterTextWithPages`；两个构建 prompt 的 summaryNodes 规则改写——**src 输出该节点核心知识点所属的 PDF 页码（纯数字，1 起始，依据「〔第 N 页〕」标记判断，跨页取起始页，无法确定输出空串，禁止臆造）**，输出格式示例改 `"src":"12"`；保留 summary 优先级规则与 max_tokens 8192。`bkParseKbJson` 无需改（src 已是字符串）。
  - `js/books-ai.js`：`bkShowOriginalText` 分流——`/^\d+$/.test(src)` → `bkOpenPdfAtPage(页码, 节点名)`；否则（旧文本数据/空）→ 原文本定位浮层。新增内嵌 PDF 阅读器：状态 `_bkPdfDoc/_bkPdfTotal/_bkPdfPageNum`；`bkOpenPdfAtPage`（渲染浮层骨架 → `window.electronAPI.readPdfFile(book.filePath)` 读本地文件 → `window.pdfjsLib || ensurePdfJs()` → `getDocument({data})`（兼容 IPC Buffer `{type:'Buffer',data:[...]}`→`new Uint8Array`）→ `_bkPdfRenderPage`）；`_bkPdfRenderPage`（`getViewport({scale:1})` 按容器宽度计算 scale≤2.5 渲染到 canvas）；`bkPdfPrev/bkPdfNext/bkPdfJump`（输入框回车/change 跳页）；`bkClosePdfReader`（`_bkPdfDoc.destroy()` + 移除浮层 + 清节点状态）；Esc 联动关闭（keydown 分支追加）。
  - `js/books-ai.js` `bkRegenerateSummary` 构建文本改用 `bkGetChapterTextWithPages`。
  - `index.html`：books-pdf `20260810-r3→20260811-r1`、books-kb `r6→r7`、books-ai `r5→r6`。
  - `css/style.css`：`.bk-pdf-panel/head/title/controls/btn/page-input/total/body/page-wrap/canvas/loading`（panel `min(1080px,94vw)`×`90vh`，canvas 白底+阴影，body 滚动）。
- 兼容旧数据：旧 summaryNodes src 是原文文本 → 仍走文本定位浮层；重新构建/重新生成摘要后获得页码数据。
- 验证：`node --check` 三个文件通过；vm 脚本 9 项 PASS（页码标记拼接/单页/空页跳过、src 页码解析、`/^\d+$/` 分流判定、截断后标记保留）。临时脚本 `_t_bkpage_test.mjs` 在根目录（删除被拒），确认后手动删。
