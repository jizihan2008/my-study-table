## 学习 tab：章节共享页（边界重叠）— 修正：不收缩

**问题（用户澄清）**：相邻章节共享同一 PDF 页（上一章 `endPage` == 下一章 `startPage`）是**正常现象**——该页既含上一章结尾也含下一章开头，**两章都应包含它**。

**踩坑**：第一版 `_stComputeChapterRange` 做了「收缩防御」（上一章终点前移、下一章起点后移），结果把共享页从**两章都剔除**，导致上一章最后一页被截掉。用户指出后才纠正。

**最终实现**（`js/books-study.js`）：`_stComputeChapterRange(book, chapter, totalPages)` **不做任何收缩**，直接返回 `{min: clamp(chapter.startPage||1, 1..total), max: clamp(chapter.endPage||total, min..total)}`。相邻共享页两章都包含。

**经验教训**：处理章节边界时，共享页（`endPage == next.startPage`）是书内正常结构，不要自作主张收缩；只有真正的页码错误（startPage>endPage）才需要兜底 clamp。

**验证**：`read_lints` 无错误。需完全重启 Electron 验证。

## 根因修复：章节切分逻辑 endPage 改为「包含共享边界页」

**问题**：切分逻辑把 `endPage` 一律算成 `下一章 startPage - 1`（假定章节间不共享页）。但教材章节边界可能**共享同一 PDF 页**（上一章最后一页 = 下一章第一页，如新章从右页起），旧逻辑把共享页算进下一章，上一章翻不到（最后一页被截）。

**修复**（`js/books-pdf.js` 三处切分路径）：
1. `splitChaptersByOutline`：`endPage = next.page`（原来 `next.page - 1`）；合并判断从 `c.startPage <= prev.endPage` 改为 `c.startPage <= prev.startPage`（只有同页/倒序才合并，正常递增章节含共享页各自独立——**否则全部误合并**）。
2. `splitChaptersAtLevel.computeEnds`：`end = nextStart`（原来 `nextStart - 1`）；clamp 同步 `end > nextStart`。
3. `aiSplitChapters`：`endPage = next.startPage`（原来 `next.startPage - 1`）。

**影响**：`bkJoinChapterText`/`getChapterText`/图片提取（`start..end` 循环）会把共享页文本/图算进两章——符合预期。`splitChaptersAtLevel` 的 `clampToParent` 在共享页下 `lastChild.endPage == n.endPage` 不触发收缩，逻辑自洽。

**重要**：章节 startPage/endPage 是导入时持久化到 `book.chapters` 的，**已导入的书需点书架「重新导入」（bkReimportBook）重建边界**；学习 tab 的 `_stComputeChapterRange` 保持不收缩（不兼容旧数据，避免误判）。

**验证**：`read_lints` 无错误。需完全重启 Electron + 重新导入书验证。

## 学习 tab：文本层（选中文字）与实际文字偏移 — 修复

**问题**：canvas 渲染用 `page.getViewport({scale*dpr})`，文本层用 `page.getViewport({scale})`，两个 viewport 不一致 → 文本层定位偏移。

**修复**（`js/books-study.js` + `css/style.css`）：
1. **canvas 与文本层共用同一个 viewport**：canvas 用 `page.render({ viewport, transform })`，dpr 高清通过 `new pdfjsLib.OutputScale()` 的 `transform=[sx,0,0,sy,0,0]` 实现（**不要**用 `scale*dpr` 的 viewport 渲染 canvas）。
2. **文本层 CSS 变量补全**（`setLayerDimensions` 依赖）：`.bk-study-pdf-text.textLayer` 定义 `--total-scale-factor:1; --scale-round-x:1px; --scale-round-y:1px`；span 定义 `--scale-x/--scale-y/--rotate` + `transform: scaleX(var(--scale-x)) scaleY(var(--scale-y)) rotate(var(--rotate))` + `font-size: calc(var(--font-height) * var(--total-scale-factor))`。
3. **JS 显式设 `--total-scale-factor = scale`**：`textDiv.style.setProperty('--total-scale-factor', String(scale))`（否则容器尺寸/字号按 1:1 原始尺寸渲染错位）。

**pdf.js TextLayer 定位原理**（4.x）：span 用**百分比定位**（`left = 100*h/pageWidth%`，基于 rawDims.pageWidth/pageHeight）；`setLayerDimensions` 用 `var(--total-scale-factor)*pageWidth` 设容器尺寸；字号 = `--font-height * --total-scale-factor`。缺任一 CSS 变量即错位。

**验证**：`read_lints` 无错误（仅预存在 line-clamp vendor 警告）。需完全重启 Electron 验证选中对齐。
